# v0.69.27-preview.25 — Windows x64 Technical Preview

This preview consolidates the changes after v0.59.0-preview.24. Windows x64
remains the demonstrated platform, Xenos D3D12 the default renderer, and Native
an experimental alternative. No game is certified as fully functional.

## Generic AOT and compatibility

- Patches 0203–0205 recover direct entries and bounded frameless callbacks
  referenced by `.data`/`.rdata`, without per-title hints. Explicit call targets
  retain precedence over speculative gap discovery.
- 0208/0209 recognize bounded `lis/addi` and `lis/ori` address materialization
  while protecting `.pdata`, inline jump tables and existing function bodies.
  Data and invalid destinations remain rejected by the negative fixtures.
- 0206 preserves UserModule export identity and reuses caller thunks; module
  unload/reload invalidates the matching registrations.
- 0207/0211 recognize complete CRT nonlocal-jump and fiber families and select
  native continuations. 0212 decodes all four PPC MD rotations in analysis.
  Dispatch through CTR and indirect calls retains checked resolution.
- Disc firmware is excluded from generic title dependencies. Original
  dashboard modules remain isolated by version and SHA-256.

Bounded, isolated Xenos D3D12 observations on 27 October reached Minecraft's
trial tutorial with movement/block extraction and Forza Horizon 2's initial
drive with HUD/minimap. Those gameplay observations used the 0212 build;
the subsequent 0214 observations verified the original system message box.
These are initial gameplay observations, not campaign, commercial save/reload,
long-session stability or FPS certification.

Fresh audit attempts on the 0214 products reached Minecraft's menu/tutorial
and Forza's opening screen, with no captured crash during controlled 180-second
attempts. They revalidated A/B completion of the original XAM box using the
newly prepared 17559 host. Brief keyboard taps did not demonstrate Minecraft
movement after the tutorial invitation or advance Forza past “Press Start”;
driving/gameplay input was not recertified. Each attempt preserved 37/37 source
console files. [Audit results and NOT RUN items](../reports/release-audit-2026-10-27.md).

## Original HUD and XAM

0213 routes `XamShowMessageBoxUI` through the original version-matched HUD/XUI,
without ImGui or automatic button selection. 0214 preserves the requesting
guest thread during asynchronous I/O completion, including OVERLAPPED and
storage-selector requests. Minecraft demonstrated A selecting button index 1
and returning success, and B cancelling with 1627/1223; Forza Horizon 2 also
returned from the original box after B. Navigation between message-box buttons
remains unverified.

The release audit reproduced 903 checks/28 XAM/UI cases, 767 checks/19 AOT cases,
3,072 native generated CTR calls, 18 bounded-dispatch calls and four native
fiber switches. Additional storage/profile tests passed 3,033 assertions in
61 cases; the independent-process achievement case was skipped in that batch
and passed separately through its write/read process script. These synthetic
contracts do not certify every original dashboard flow.

## Xenos and Native graphics

- Xenos 0196–0198 integrate Vulkan upload synchronization, MSAA/sample-position
  contracts and EDRAM offsets/wrapping/aliases. 0199/0200 implement gamma PWL;
  0201 corrects full-resolve fixed16 s5.10; 0202 implements exact scaled MSAA
  RGB565 addressing. DXBC/SPIR-V regeneration and locked hashes are preserved.
- The audit reran 2,324 cases per API on D3D12/Vulkan. Fixed16 had zero oracle
  failures. All 45 historical R8 differences per API remain explicitly
  classified. API-specific FP16 RTZ/RTE differences retain their expectations.
- Native Vulkan defers writeback publication by submission/fence while
  preserving ordered guest-visible reads, events and CPU-generation checks.
  N-PERF-01 historically measured export 1× batches at 440.23 → 164.89 ms and
  resolve 1× at 408.23 → 197.66 ms, with seven alternating pairs. These are
  synthetic batch timings, not game FPS. Synchronous/no-writeback controls
  included results without improvement; see the complete methodology.
- Regression screening against the retained integrated implementation used
  three alternating pairs of 4,096 operations per scenario on the same RTX
  4070/617.42, without concurrent builds/GPU tests. Paired batch changes were
  +2.18% export 1×, −7.80% resolve 1×, +0.36% synchronous control, −35.54%
  no-writeback control (wide variation), −0.71% resolve 2× and −0.18% resolve
  4×. Default instrumentation-OFF export/resolve were −0.93%/−1.23%.
  All byte comparisons passed; this small screening found no severe
  reproducible regression and does not establish a new performance gain.
- The audit found a missing RenderDoc header dependency in the standalone
  Native Vulkan probe and corrected its CMake include. Its ABI probe now
  checks enabled Vulkan identity and rejects invalid APIs/ABI/create-info,
  preserving the no-fallback and no-Xenos-loading controls.
- Two session test fixtures now supply the complete catalog metadata required
  by production. Their positive and version/file-rejection expectations remain
  intact; no runtime check was weakened.

## Known limitations

Native MEMEXPORT still fails incomplete VS-only triangles and resident alias
updates; Vulkan additionally fails four signed integer packing cases. Both
Native occlusion probes still fail guest-alias invalidation after ZPD physical
publication. The audit reproduced identical full outputs and exit codes in
the retained baseline and current build. These failures were not fixed or
converted into passes. Khronos validation layers were unavailable locally.

Charlie Murder remains limited to its previously demonstrated AOT/module and
NetCF bootstrap contracts; XNA gameplay is unverified. Dashboard 6717 retains
its missing matching-resource limitation. Original services, multiple active
users, commercial save/reload, clean Windows first use and other operating
systems remain incomplete or unverified. See the [compatibility matrix](../compatibility.md).

## Installation and data preservation

Download `x360-native-0.69.27-preview.25-windows-x64.zip` and its `.zip.sha256`.
Verify the checksum, extract the complete ZIP into a new directory and run
`x360-native.exe`. Import and prepare only authorized local content, then
start its original dashboard. Preparation requires the declared pinned tools;
the ZIP does not contain a complete development toolchain.

Keep the previous installation and its `data/` directory intact. Back up profiles,
the virtual HDD and saves before choosing an environment; do not extract over
an existing environment or move original modules between dashboard versions.
Old preparation receipts may require rebuilding after SDK/source changes.
There is no claim of commercial save compatibility or automatic data migration.

ReXGlue remains pinned to `f5337cdc947ff6d4c4196737e2c807a48f2a1fc2`:
clean replay of 201 active patches reproduced all 271 final file hashes.
The official hosted workflow builds Release Windows x64, checks catalog/update
recovery, licenses/content, ZIP inventories, checksums and provenance. Games,
XEX, firmware, original dashboards, profiles, saves and developer caches are
excluded. Publication requires the manual workflow gate on the final main SHA
before its immutable tag is pushed.
