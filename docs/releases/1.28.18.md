# x360-native v1.28.18 — Stable Release

This stable release completes the Windows path work started in v1.28.17. The launcher, importer, catalog, preparation and update code now share one filesystem layer, so installations in deep, Unicode or network (UNC) folders work without changing any Windows setting.

## Fixed

- **One filesystem layer:** every file operation of the launcher, extraction, import, catalog, SHA-256 verification, preparation, update and removal goes through the same layer. Paths stay ordinary everywhere and are converted to the Windows extended-length form (`\\?\` or `\\?\UNC\`) only at the moment of I/O, up to about 32,000 characters. Ancestor walks never use the extended form.
- **Direct Windows calls:** locks and C runtime opens that bypassed the shared layer now use the extended form too. Every file move and replacement (imported games, the catalog, extraction manifests, storage, console and graphics settings, update transactions, preparation checkpoints and pipeline caches) now uses one rename of that layer instead of its own call. A file published in its own folder names only its new file name, so it also works on network shares at any depth.
- **Junctions:** Windows junctions are treated as links by the containment checks, like symbolic links, at any depth.
- **Unicode:** the launcher, the command-line tools and the desktop app run with the UTF-8 code page, and configuration files are read from deep and Unicode folders.
- **Network folders:** installations on a UNC share resolve correctly even when a folder name holds characters that the share cannot normalize, such as emoji.
- **Processes from deep folders:** Windows cannot start a process in a folder beyond 258 characters. Such a process now starts in the same folder reached through a short junction to its installation, `%LOCALAPPDATA%\x360n\r\<id>`, which needs no privilege or Windows setting. Relative paths and `..` resolve exactly as in the original folder, and short (8.3) names are no longer used, so volumes without them work. The junction is checked before every use: one pointing elsewhere is replaced without touching its target, and any other file in its place is refused.
- **Preparation from long installations:** Windows PowerShell 5.1, `cmd`, CMake, Ninja and the compilers cannot open names beyond 260 characters without a Windows policy, and they reach about 180 characters below the installation folder. When the installation folder leaves less room, preparation reaches it through the same junction. Content, saves and title outputs stay in the installation. Programs are started by their ordinary name whenever it fits, because Windows PowerShell 5.1 fails to start from an extended (`\\?\`) name. Git runs with `core.longpaths`, and through the junction it runs without MinGit's `cmd\git.exe` launcher, which would leave the junction and break `git submodule`.
- **Installations too long to prepare:** CMake and Git resolve the junction to the real folder. CMake names its own modules up to 119 characters below it, and Ninja refuses names over 260 bytes of UTF-8. Git opens the SDK repository's metadata, up to 102 characters below it, before it applies `core.longpaths`. Preparation on Windows therefore needs an installation folder of at most 141 bytes in UTF-8: 141 plain letters, fewer with accents (2 bytes), Asian characters (3) or emoji (4). A longer folder is refused before any tool starts, with its size and the limit, instead of failing inside CMake or Git. Importing into deeper folders works (checked at 265 characters).
- **Short, isolated title builds:** CMake and Ninja cannot pass 260 characters without a Windows policy change. Each title is now compiled in a short private folder under `%LOCALAPPDATA%\x360n\b`, and its executable and modules are copied next to its receipt in the installation. Games, dashboards and user data stay where they are, at any depth. The old build files left in the installation are removed after the next preparation, and removing an imported game also removes its build folder. If you delete that build folder yourself, prepare the title again.

## Updating

The launcher checks GitHub Releases at startup and offers newer stable versions after asking you. It verifies the downloaded archive before installing it and keeps your data, imported games, saves and profiles. Because titles now build in a new folder, the launcher shows the dashboard and your games as needing preparation again; the first preparation after the update compiles them from scratch.

## Verification and limitations

New tests create, read, list, hash, copy, replace, rename and remove files at 100, 259, 260, 320, 500, 1024, 1100 and 2048 characters, with Unicode names and the `DLC_Rob_Fant_[0x2a2c7864e22311ee].loc` name. They also cover `..`, relative and missing paths, junctions and symbolic links, real UNC shares (`\\localhost\<drive>$`, up to 1,100 characters), processes started from deep folders, Windows PowerShell 5.1 started through the junction, and the preparation limit, which is checked against this checkout's Git metadata and CMake modules. They run on all six package builds. The symbolic-link case needs a privilege that the test account lacks, so it is reported as skipped, not as passed.

End to end on Windows x64, on an NTFS volume without short (8.3) names, in a 121-character, 141-byte installation folder with accents, Chinese, Japanese and an emoji: the launcher imported the 17559 dashboard and Castle Crashers, prepared both (tools, shared SDK, codegen, configuration and build through the junction), and started the dashboard. My Games then launched Castle Crashers, which reached gameplay. A 168-character folder was refused before any tool started, with the message above. Passing this does not prove that every original game behaves correctly in a deep folder; check your library by hand with this release.

Remaining limits: preparation on Windows needs an installation folder of at most 141 bytes in UTF-8, as explained above. On a network share, preparation and processes cannot use a junction, so they need ordinary path lengths there. Windows refuses to move a file between folders on a share once the share-relative name passes about 500 characters (renames within a folder work at any depth). On macOS a path cannot reach 1,024 bytes, a system limit. Title builds need `%LOCALAPPDATA%` itself to be short (the build folder must stay within 69 characters); otherwise preparation stops with a message. The crash of the 17559 dashboard right after creating a profile is still open. Windows x64 is still the only platform with end-to-end evidence. No new game compatibility or GPU performance is claimed.
