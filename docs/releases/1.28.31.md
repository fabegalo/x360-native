# x360-native v1.28.31 — Stable Release

This stable release follows v1.28.30 and completes the fix for preparing Motocross Madness in an installed package. Everything else is unchanged.

## Fixed

- **Motocross Madness still could not be prepared in an installed package:** after v1.28.30, preparation stopped with `canonical: The system cannot find the path specified` for `…\.local\inputs\dashboards\17559\retail_system_assets\extracted\xam.xex`. The title compiles the original XAM 2.0.17559.0, and its profile named a folder that only a development checkout had. It now uses the copy the Retail 17559 dashboard import places (`dashboards\17559\runtime\system\xam_ui.xex`, the same SHA-256 `78b3dbd8…`), the file its avatar service already uses during the session. The module is now built as `motocross_madness_xam_ui.dll`. A new test requires every original that a registered title compiles to be placed by an import; it failed only for Motocross Madness before this fix.

Import the Retail 17559 dashboard before preparing Motocross Madness, which already needed that dashboard to start.

## Updating

The launcher checks GitHub Releases at startup and offers newer stable versions after asking you. It verifies the downloaded archive before installing it and keeps your data, imported games, saves and profiles. Motocross Madness needs preparation after this update. For other titles the full check decides, as before.

## Verification and limitations

On Windows x64, in a development checkout with the Retail 17559 dashboard imported, Motocross Madness was prepared from start to finish with this change (exit code 0, through the `prepared` stage). The new module target kept its host function table and diagnostic hooks. The preparation tests pass (19 test cases). The game was not started after this preparation, and preparation from an installed release package was not run before publication. The open limitations of [v1.28.28](1.28.28.md) still apply. Windows x64 is still the only platform with end-to-end evidence.
