# x360-native v1.28.12 — Windows First-Use Build Path Hotfix

This stable maintenance release addresses a first-use preparation failure in the Windows launcher that could occur after extracting the application to an ordinary folder, including a Desktop installation.

## Fixed

- **ReXGlue / SDL3 path overflow in Windows installations:** the shared SDK was built under a deeply nested `data/environment/.local/build/shared-sdk` directory. During SDL3 architecture detection, CMake's `try_compile` generated object paths beyond its supported limit (266 characters versus a 250-character object path budget), and Ninja could fail to open `CMakeFiles/rules.ninja`.
- **Short and isolated shared-SDK build location:** Windows uses a persistent, per-installation user-local build directory rather than nesting generated SDK build products under the launcher directory. The original installation, imported content, title build locations, user profiles, virtual storage and saves are preserved.
- **Protected Ninja supervision:** the build-owner guard permits the designated short SDK build area without allowing unrelated external build directories.
- **Regression tests:** tests cover SDK generation-path length, stable generation identities and invalid path identities. Linux and macOS retain their previous SDK build layout.

## Installation and upgrading

Extract into a new folder. Back up and preserve `data/`, your library, original dashboard/game files, profiles, saves and virtual drives. Previous compiled builds may require preparation again after SDK changes. Do not overwrite an active installation.

The launcher contains no original Xbox 360 games, firmware or system resources. Users provide legally obtained content for import and preparation.

## Limitations

- These fixes target path handling and preparation; they do **not** certify a game's stability, full gameplay or improved FPS.
- Windows x64 with Xenos D3D12 has the strongest observed gameplay and dashboard flows. Other systems, dashboard versions and Native/Vulkan paths remain experimental.
- Passing CI compilation/packaging and synthetic path tests is not proof that full SDL3/ReXGlue preparation succeeds on every clean Windows machine. A real extracted-archive first-use test with a long installation path is still required.
